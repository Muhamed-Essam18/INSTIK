# Tasks: Roles, Creator Invites and Content in the Database

**Input**: Design documents from `/specs/008-roles-invites-content-db/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

**Tests**: Included. Constitution IX requires tests for core logic, and XI requires role and ownership tests that include a creator trying to reach another creator's data. Tests live in `tests/unit/` (Vitest includes `tests/**/*.test.{ts,tsx}`). Data access is tested through injected in-memory stores, as `tests/unit/billing/` does; no test needs a database.

**Organization**: Grouped by user story. The two P1 stories depend on each other for data: US2 (import) is built before US1 (learner site reads) so there is content to read, and US1 is the first story that can be shown to a learner. US3 and US4 (P2) and US5 (P3) build on the Foundational phase.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: US1 to US5 from spec.md

**Before writing any Next.js code**: read the relevant guides in `node_modules/next/dist/docs/` (AGENTS.md): at least `01-app/01-getting-started/16-proxy.md`, `08-caching.md` (Cache Components with runtime data) and `15-route-handlers.md`, and `generateStaticParams` / `notFound` in the API reference. Use design tokens from `src/app/globals.css` only. Never commit secrets or real emails.
