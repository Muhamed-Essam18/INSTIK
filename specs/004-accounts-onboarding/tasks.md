# Tasks: Accounts and Onboarding

**Input**: Design documents from `/specs/004-accounts-onboarding/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

**Tests**: Included. The plan asks for tests of onboarding carry-over and the per-language profile rules, and constitution principle IX requires tests for core logic (access rules here). Write each test first and see it fail. Auth.js, Prisma and Resend are not unit tested; they are checked by build and the quickstart.

**Organization**: Grouped by user story. Phases are ordered by dependency rather than by story number: US2 (sign in and out) comes first because the onboarding sign-up step (US1) uses its form and actions. US7's account menu and user slot (T071â€“T075) are built right after US2 because sign-out lives there and the MVP needs it. Pure rules (profile rules, return-to, gate, env) sit in Foundational because several stories share them. Task IDs are stable labels and do not follow file order: T079 is a precondition in Phase 1, T071â€“T075 sit in Phase 4, and T082â€“T085 were added after the first draft.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on unfinished tasks)
- **[Story]**: US1 Join through onboarding (P1), US2 Sign in and out (P1), US3 Browse freely, sign in to watch (P1), US4 Choices before signing up are kept (P1), US5 Profile per language and adding one (P2), US6 Transcript choices follow me (P2), US7 Account button and menu (P2)

## Path Conventions

Single Next.js app: `src/`, `tests/unit/`, `prisma/`, `content/` at the repository root. Before writing Next.js code, read the relevant guide in `node_modules/next/dist/docs/` (AGENTS.md): proxy (`01-app/01-getting-started/16-proxy.md`), `02-guides/authentication.md`, `02-guides/authentication-with-cache-components.md`, `02-guides/environment-variables.md`, `02-guides/data-security.md`. Middleware is called **Proxy** here (`src/proxy.ts`). Nothing in a render path may read `window`, `localStorage`, `Date` or randomness; browser reads go in effects or event handlers. Files that touch the database, secrets or the session start with `import "server-only"`. Learner-facing copy follows the brand voice: short, warm, never shaming; no mention of passwords, streaks, scores or internal level names.
